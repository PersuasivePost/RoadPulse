## Blockers / notes

- F1: no `crack` class (no suitable close-up dataset). Dataset sources are skewed (see REPORT caveats): re-test with real phone photos on Mac visit 2. Vision must use `imageCropAndScaleOption = .scaleFill`. Model can't be run on Linux; first real prediction check is the F5 XCTests on CI.
- F2: a v2 model can't be migrated by the flags alone, because there's no .momd for Core Data to find v1 in. `ModelBuilder` documents the `NSStagedMigrationManager` route (iOS 17).
- F3: `PrimaryButton` forces the `ink` label to its light-mode (dark) value; DESIGN.md says `ink` on `laneYellow`, but in dark mode `ink` is near-white and unreadable on yellow. Apply the same trick to the selected `FilterChip`.
- F3: onboarding only prompts for location. Camera and motion prompts come from iOS on first use (`UIImagePickerController` / CoreMotion), so no extra framework is needed.
- F3: `LocationManager` is authorization-only; F4 adds updates and the denied-state view.
- F4 / Mac visit 1: to move the blue dot, run on a simulator, then Xcode → Debug → Simulate Location → MumbaiCommute (the GPX is in the project, so it is listed). It isn't set as the scheme default because the XcodeGen `simulateLocation` path syntax couldn't be verified without a Mac and a wrong value would break `xcodegen generate`.
- F4: no Drive Mode FAB yet; DESIGN.md puts it on the map, but the Drive sheet is F8, so a button now would do nothing.
- F4: the `LocationManager` is now one shared instance in the environment (done in F5); `RootTabView` starts it once.
- F5: first real Core ML run is the CI tests. If `ClassifierServiceTests` fails on confidence, compare Vision's `.scaleFill` scaling with `ml/dataset.py`'s eval transform before touching the model.
- F5: the OCR test depends on Vision text recognition working in the CI simulator; if it fails there, fix the test setup rather than skipping it.
- F5: without a location fix (simulator default is none) the Review button stays disabled by design. Use Debug → Simulate Location (the GPX) or Features → Location → Custom Location.
- F5: the "Try a sample photo" and "Use sample signboard" menus are simulator-only (`#if targetEnvironment(simulator)`), so a real device never shows them.
- F4: Xcode doesn't copy `.gpx` into the app bundle (it's a location-simulation file), so the GPX test reads it from the source tree via `#filePath`.
- F6/F7: pull-to-refresh re-reads Core Data, then fetches rainfall for hazards without it (max 10 per pull).
- F7: rainfall = sum of Open-Meteo `precipitation_sum` for `past_days=6` + today (7 days). Demo hazards already have rainfall; new reports fetch it when opened. Test with Airplane Mode for the error + Retry state on Mac visit 2.
- F6: the detail is an in-screen overlay rather than a pushed screen, because `matchedGeometryEffect` can't span a `NavigationStack` push on iOS 17. Check the hero morph and the jump-to-top button (first-row `onAppear` tracking) on the Mac.

- F8: the replay CSV carries its own lat/lon (the GPX isn't copied into the app bundle), so the trail appears around Kalyan–Dombivli without Simulate Location. Live drives use `LocationManager`'s latest fix (10 m distance filter), so a short rough patch on a real drive may be drawn as a dot.
